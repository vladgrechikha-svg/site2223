# Orders CRM

Збирає замовлення з Prom, Rozetka та вашого сайту (через webhook) в одну стрічку,
дозволяє одним кліком створити накладну Нової Пошти, і шле сповіщення в Telegram
про кожне нове замовлення.

## Встановлення

```
npm install
cp .env.example .env
```

Відкрийте `.env` і впишіть свої реальні ключі (ті, що ви вже мали з Prom, Kasta,
Rozetka, Нової Пошти). **Файл `.env` ніколи не публікуйте і не комітьте в git** —
додайте його в `.gitignore`. Це єдине місце, де мають жити ваші ключі.

Запуск:

```
npm start
```

Дашборд буде на `http://localhost:3000`.

## Деплой (щоб система працювала постійно, не тільки на вашому комп'ютері)

Потрібен хостинг, що тримає Node.js-процес запущеним 24/7 — наприклад Render.com,
Railway.app або звичайний VPS з pm2. При деплої ключі вписуються в
розділ "Environment variables" хостингу — не в код.

## Що вже працює

* **Ваш сайт → CRM**: `POST /webhook/site-order` приймає замовлення (JSON) і
показує в дашборді з міткою "Сайт" + шле Telegram-сповіщення.
* **Prom / Rozetka**: сервер сам раз на `SYNC\_INTERVAL\_MINUTES` хвилин опитує
їхні API і підтягує нові замовлення (можна й вручну — кнопка "Оновити зараз").
* **Нова Пошта**: кнопка "Згенерувати" створює ЕН автоматично, підставляючи
місто/відділення клієнта і дані вашого відправника з `.env`.
* **Дашборд**: `/` — стрічка останніх 50 замовлень з фільтром по джерелу.

## Що потребує уваги перед першим реальним використанням

1. **Prom і Rozetka API з часом змінюються.** Я написав інтеграції за
документацією станом на зараз, але не мав змоги протестувати їх на живому
акаунті (з цього середовища немає мережевого доступу до prom.ua чи
rozetka.com.ua). Перед тим як довіряти системі реальні замовлення —
запустіть `POST /api/sync` і перевірте, чи коректно підтягуються дані;
якщо якесь поле не мапиться — треба буде підправити `integrations/prom.js`
/ `integrations/rozetka.js` під актуальну структуру відповіді.
2. **Дані відправника для Нової Пошти** (`NP\_SENDER\_\*` в `.env`) — це Ref-и
(GUID) з вашого кабінету НП, не просто назви. Їх можна знайти через
API-метод `Address.getCounterparties` / у самому кабінеті НП, або
попросити розробника один раз "прошити" їх.
3. **Kasta, OLX, EasyDrop, TikTok, Instagram** — свідомо не підключені. Як я
писав раніше: у Kasta й OLX немає відкритого API для звичайних продавців,
EasyDrop працює через Telegram-бота (не REST API), а Instagram/TikTok —
це вже інша інтеграція (Meta/TikTok Business Messaging API з
верифікацією бізнесу). Якщо потрібно — це окремі, більші підзадачі.
4. **Комісія маркетплейсу і баланс на Prom** — Prom API віддає ці дані в
інших ендпоінтах (баланс — окремий запит до кабінету), зараз вони не
заповнюються. Можна додати окремим наступним кроком.

## Структура проєкту

```
server.js               — головний сервер, всі маршрути
db.js                   — файлова база (orders.json), без окремого сервера БД
integrations/prom.js     — підтягування замовлень з Prom
integrations/rozetka.js  — підтягування замовлень з Rozetka
integrations/novaposhta.js — пошук міста/відділення і створення ЕН
integrations/telegram.js — сповіщення в Telegram
public/index.html        — дашборд (те, що бачите у браузері)
```
